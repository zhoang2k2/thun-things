# P6 — Cookie Consent & GA4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (owner chose native execution, no subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bilingual consent bar gates GA4: nothing loads from Google before Accept, five typed events without personal data reach GA4 afterwards, and the choice is revocable from the footer.

**Architecture:** Client `ConsentProvider` over `localStorage` (`lib/analytics/consent.ts`), lazy `Analytics` component rendering `@next/third-parties` `GoogleAnalytics` only when consent and `analyticsMode` allow, typed `trackEvent` helper, CSP widened to the Google tag and collection origins only.

**Tech Stack:** Next.js 16.4 (Cache Components), next-intl 4.14, `@next/third-parties` 16.4.2 (installed since P0), React 19, Vitest + RTL, Playwright + axe.

**Spec:** [`../specs/2026-10-24-p6-consent-ga4-design.md`](../specs/2026-10-24-p6-consent-ga4-design.md).

**Branch / PR:** `phase/p6-consent-ga4` from `develop` after P5 (#7) merges → one PR, evidence via `pnpm evidence`.

## Global Constraints

- Consent Mode Basic: zero requests to `*.google.com`, `*.googletagmanager.com`, `*.google-analytics.com`, `*.analytics.google.com` before Accept (tests count them).
- `ad_storage`, `ad_user_data`, `ad_personalization` always `denied`; `analytics_storage` follows consent.
- GA runs only when `NEXT_PUBLIC_GA_ID` is set **and** (`VERCEL_ENV === 'production'` or the tab has `?ga_debug=1`). No new environment variable.
- Event params never carry email, phone, name, address or free text; allowed keys per spec section 5.
- Keep P4/P5 guarantees: render modes unchanged (Home and Contact ◐, others ○/●), Lighthouse budgets (LCP < 2500 ms, CLS < 0.1, TBT < 200 ms), axe zero serious, both locales, DR-1/DR-2, client messages scoped (only the `consent` namespace added to the root client subset).
- The banner is client-only after hydration; it must not change the prerendered HTML or cause layout shift.
- Playwright build uses `NEXT_PUBLIC_GA_ID=G-TEST000000` and intercepts all Google traffic — the real ID is never contacted from tests.

## Review Focus

1. **Request before consent** (fast first click, back/forward cache, a second tab that accepted) → still zero Google requests until this tab's state says granted. Pinned in Task 2.
2. **Storage unavailable** (Safari private mode throws on `localStorage`) → banner works for the session, no crash, GA stays off. Pinned in Task 1.
3. **Revoke after accept** → `_ga*` cookies removed and no further `collect` requests, even though gtag stays loaded. Pinned in Task 2/3.
4. **PII leak via params or URL** → event helper rejects unknown keys at the type level and a test scans every intercepted `collect` payload for the test email/phone. Pinned in Task 3.
5. **Banner covering the order bar or trapping focus** on mobile product pages → stacked layout and keyboard order verified. Pinned in Task 1/4.

## Implementation notes (2026-10-24)

- Own minimal Google tag loader instead of `@next/third-parties` `GoogleAnalytics`, so `consent default` always runs before `config`.
- The consent bar is prerendered with an inline boot script (spec section 2 updated): client-only rendering made it the LCP element at ~3 s while images are placeholders.
- `product_id` in events is the product slug. `contact_start` sent before the streamed contact prefill resolves has no `product_id` (no fallback to the raw `?product=` query, which is free user text).
- Existing E2E specs start with a stored consent decision (`e2e/fixtures/consent-decided.json`); `e2e/consent.spec.ts` starts without one.
- Fixed a pre-existing race in `e2e/security.spec.ts` (scrolling to the last tile before the grid finished streaming).
- Lighthouse (first-visit state, bar showing): LCP 1.97–2.41 s, CLS 0, TBT ≤ 41 ms — `docs/reports/lighthouse-p6-2026-10-24/`.
