# P5 — Internationalization (vi/en) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every page is served at `/vi/...` and `/en/...` through `next-intl`, with natural English copy, a path-preserving switcher, bilingual SEO, and locale-aware forms, keeping every P4 guarantee (prerendered shells, CSP, budgets, SEO and a11y checks).

**Architecture:** `app/[locale]/` is the root segment (root params via `next/root-params`), `next-intl` routing with `localePrefix: 'always'` and no detection, messages in `messages/{vi,en}.json` typed through `AppConfig`, `proxy.ts` composing next-intl middleware with the product 404 rewrite and legacy redirects. Non-page routes stay at `app/` root.

**Tech Stack:** Next.js 16.4 (Cache Components, `next/root-params`), `next-intl` 4.14.9 (installed since P0), React 19, Zod 4, Vitest + RTL, Playwright + axe.

**Spec:** [`../specs/2026-10-23-p5-i18n-design.md`](../specs/2026-10-23-p5-i18n-design.md).

**Branch / PR:** `phase/p5-i18n` from `develop` → one PR, evidence via `pnpm evidence`.

## Global Constraints

- Locales `['vi', 'en']`, default `vi`, `localePrefix: 'always'`, `localeDetection: false`; `/` → `/vi`; legacy unprefixed page paths → `/vi/...` (permanent, query kept).
- Slugs identical in both locales; product content comes from the catalog's `Localized` fields, not translated or edited (P5-3).
- English copy rules (spec): rewrite for English readers, search phrases only where true, no filler, no exclamation marks or emoji, no new promises, `[Owner to update: …]` placeholders, descriptions 50–160 characters, unique per page and locale.
- `next/root-params` is unavailable in Server Actions and Route Handlers: server functions get the locale from a validated hidden field; `llms.txt`, sitemap and robots take locales from `i18n/routing.ts`.
- Keep P4 guarantees: render modes unchanged from P4 (Home and Contact partially prerendered ◐, every other page static ○/●, products ● from static params), in both locales; CSP unchanged (no new origins); Lighthouse budgets; all P4 SEO/axe/keyboard/reduced-motion/smoke checks pass for both locales.
- No client component receives the full message bundle: `NextIntlClientProvider` gets only the namespaces its children use.
- Read first: `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/next-root-params.md`, next-intl's docs/README in `node_modules/next-intl`, and the Next `proxy`, `not-found`, `generateStaticParams` pages.

## Review Focus

1. **Lost prerendering:** reading the locale must not turn static pages dynamic → `pnpm build` route table compared with P4 (Task 2 records both).
2. **Unknown or malformed locale** (`/fr`, `/vi-VN`, `/EN`) → 404, never a crash or a redirect loop. Pinned in Task 2.
3. **Legacy links with queries** (`/contact?product=am-ban&purpose=notify`) → `/vi/contact?product=am-ban&purpose=notify` in one hop. Pinned in Task 2.
4. **Switcher on pages with queries and on 404** keeps path and query, and on the 404 still offers a working link. Pinned in Task 2/6.
5. **Forged locale in a form post** (`locale=xx`) → treated as `vi`, no crash, lead stored with a valid locale. Pinned in Task 5.

## Implementation notes (Tasks 4–7, 2026-10-24)

Tasks 4–7 were first implemented in a separate session that could not run the build or browser suites, then adopted, verified and committed by the integration pass.

- **Rendering:** `pnpm build` route table matches P4 per locale: `/vi`, `/en`, `/vi/contact`, `/en/contact` ◐; about, policies, contact result pages and `/{locale}/not-found-page` ○; 48 product pages and 48 product OG images prerendered from static params. The `/[locale]/…` ◐ rows are fallback shells that the proxy never lets through.
- **English 404:** `proxy.ts` allow-lists page paths and known slugs and rewrites every other path to `/{locale}/not-found-page` (Vietnamese for unprefixed or unknown-locale paths). The page renders the 404 body and calls `notFound()` inside Suspense, so the prerender keeps the HTML and records status 404 (a page-level `notFound()` prerendered an empty client-only error shell; the rewrite's own `status` is ignored for prerendered pages). `app/global-not-found.tsx` only serves misses the proxy never sees.
- **`metadataBase` warnings:** caused by the root `app/opengraph-image.tsx` file convention, which sits above the `[locale]` root layout and outside every `metadataBase`. It is now a route handler at the same URL (`app/opengraph-image/route.ts`); pages already referenced `/opengraph-image` explicitly, so absolute URLs are unchanged.
- **No-JS switch:** owner-accepted exception (spec section 3, ADR-008): path kept, query dropped. A same-origin `/language/[target]` redirect endpoint that recovered the query from `Referer` was prototyped and removed as out of scope.
- **Metadata:** Home page 1 gets a tagline title (`Thun Things · Áo thun nghệ thuật` / `Thun Things · Art T-shirts in small runs`, `pages.home.metaTitle`). Product meta descriptions shorter than 50 characters (English `mat-ho`) append the catalog's existing material field; catalog copy is unchanged.
- **JSON-LD:** `inLanguage` only on `WebSite`; schema.org does not define it for Organization or Product, whose fields and URLs follow the page locale instead.
- **Hidden previous route:** after a client-side locale switch, Next keeps the previous locale's tree in the DOM with `display: none` for back/forward. Scripts that query the DOM use `:visible` or role-based locators.
- **Lighthouse:** `docs/reports/lighthouse-p5-2026-10-24/`. Home SEO stays at 91 as in P4 (its metadata streams after the shell for ordinary browsers; bots in `htmlLimitedBots` get it in `<head>`).
