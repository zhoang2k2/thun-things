## 2. Rules [USER]

### R1 — Phase gate

A phase may start only when the previous phase is **DONE**. A phase is DONE when **all** of the following are true:

1. Every FE and BE task checkbox in the phase plan is ticked.
2. The phase's own **Acceptance** list is satisfied.
3. The global Definition of Done (section 3) passes.
4. The phase PR is merged into `develop` by the owner.
5. The phase status in section 5 is updated to `DONE`.

### R2 — Fast-track

A later phase may start before its turn **only if**:

1. Every **Owner** task of that later phase is DONE (information supplied, spec clarified, env values set), **and**
2. Every phase listed in its **Depends on** line is DONE.

A fast-tracked phase still gets its own branch and PR. It must not modify code owned by an unfinished phase except through that phase's agreed interfaces.

### R3 — One phase = one PR, one task = one small commit

- Branch per phase from `develop`: `phase/pN-<slug>` (e.g. `phase/p0-foundations`).
- One PR per phase into `develop`. Never commit directly to `main` or `develop`.
- Each task in the phase plan lands as one or more small commits: `[TYPE] Imperative summary` (`[TASK]`, `[FEATURE]`, `[FIX]`, `[ENHANCE]`, `[REFACTOR]`, `[CHORE]`, `[DOCS]`).
- Every commit leaves `pnpm typecheck`, `pnpm lint`, and `pnpm test` green.

### R4 — Environment ownership

- Agents **must not read** `.env`, `.env.local`, `.env.*.local`, or any real secret. Only `.env.example` and `docs/configuration-variables.md` are readable.
- Agents **predict and declare** every variable ahead of time: schema in `lib/env.ts`, placeholders in `.env.example`, purpose and phase in [`docs/configuration-variables.md`](../../configuration-variables.md).
- Every variable not needed by the current phase is **optional** in the schema, so a missing value never crashes `dev`, `build`, or CI. Features that need a missing value degrade to a disabled state.
- The **Owner** sets real values in `.env.local` and Vercel before the phase that requires them starts. A missing required value is a blocker for that phase, not something agents work around.

## 3. Definition of Done (every phase)

1. `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, `pnpm build` all pass locally and in CI.
2. New interactive components have React Testing Library tests; user-facing flows have a Playwright smoke test.
3. Accessibility: keyboard reachable, visible focus, labels, `prefers-reduced-motion` respected; no serious axe issues on touched pages.
4. Performance budget not regressed (mobile): LCP < 2.5 s, INP < 200 ms, CLS < 0.1.
5. No hard-coded user-facing strings outside the copy module (`content/copy/`) — this keeps P5 i18n a mechanical change.
6. `docs/decisions/` updated if a decision changed; `docs/configuration-variables.md` updated if a variable changed.
7. Vercel preview deploy of the PR is reachable (from P1 onward).
