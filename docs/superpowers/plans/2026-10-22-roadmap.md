## 2. Rules [USER]

### R1 — Phase gate

A phase may start only when the previous phase is **DONE**. A phase is DONE when **all** of the following are true:

1. Every FE and BE task checkbox in the phase plan is ticked.
2. The phase's own **Acceptance** list is satisfied.
3. The global Definition of Done (section 3) passes.
4. The phase PR is merged into `develop` by the owner.
5. The phase status in section 5 is updated to `DONE`.

### R2 — Fast-track

A later phase may start before its turn **only if**:

1. Every **Owner** task of that later phase is DONE (information supplied, spec clarified, env values set), **and**
2. Every phase listed in its **Depends on** line is DONE.

A fast-tracked phase still gets its own branch and PR. It must not modify code owned by an unfinished phase except through that phase's agreed interfaces.

### R3 — One phase = one PR, one task = one small commit

- Branch per phase from `develop`: `phase/pN-<slug>` (e.g. `phase/p0-foundations`).
- One PR per phase into `develop`. Never commit directly to `main` or `develop`.
- Each task in the phase plan lands as one or more small commits: `[TYPE] Imperative summary` (`[TASK]`, `[FEATURE]`, `[FIX]`, `[ENHANCE]`, `[REFACTOR]`, `[CHORE]`, `[DOCS]`).
- Every commit leaves `pnpm typecheck`, `pnpm lint`, and `pnpm test` green.

### R4 — Environment ownership

- Agents **must not read** `.env`, `.env.local`, `.env.*.local`, or any real secret. Only `.env.example` and `docs/configuration-variables.md` are readable.
- Agents **predict and declare** every variable ahead of time: schema in `lib/env.ts`, placeholders in `.env.example`, purpose and phase in [`docs/configuration-variables.md`](../../configuration-variables.md).
- Every variable not needed by the current phase is **optional** in the schema, so a missing value never crashes `dev`, `build`, or CI. Features that need a missing value degrade to a disabled state.
- The **Owner** sets real values in `.env.local` and Vercel before the phase that requires them starts. A missing required value is a blocker for that phase, not something agents work around.

## 3. Definition of Done (every phase)

1. `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, `pnpm build` all pass locally and in CI.
2. New interactive components have React Testing Library tests; user-facing flows have a Playwright smoke test.
3. Accessibility: keyboard reachable, visible focus, labels, `prefers-reduced-motion` respected; no serious axe issues on touched pages.
4. Performance budget not regressed (mobile): LCP < 2.5 s, INP < 200 ms, CLS < 0.1.
5. No hard-coded user-facing strings outside the copy module (`content/copy/`) — this keeps P5 i18n a mechanical change.
6. `docs/decisions/` updated if a decision changed; `docs/configuration-variables.md` updated if a variable changed.
7. Vercel preview deploy of the PR is reachable (from P1 onward).

### P3 — Contact, notify-me & policy pages

Design: [`../specs/2026-10-23-p3-contact-forms-design.md`](../specs/2026-10-23-p3-contact-forms-design.md). Plan: [`2026-10-23-p3-contact-forms.md`](./2026-10-23-p3-contact-forms.md). - **FE:** Contact page form (product prefilled from query; order fallback while no chat channel); in-page notify-me form on sold-out product pages (V-22); accessible errors and success state; Policy and About content.
- **BE:** `POST /api/contact` and notify-me submission with Zod validation, honeypot, rate limit (Upstash); `lib/leads/sink.ts` interface + `email.ts` (Resend); forms disabled gracefully when email env is missing.
- **Owner:** Create the local env file from the example and fill P3 values; Resend account + API key; inbox address; Upstash Redis; policy text (returns, privacy); About text + photo; chat channel links when available.
- **Env required:** `RESEND_API_KEY`, `LEADS_TO_EMAIL`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (`LEADS_FROM_EMAIL` and `CUSTOMER_CONFIRMATION_ENABLED` keep their defaults until P9).

- **Owner:** English copy review (or approve agent translation); English product copy.

- **BE:** `lib/analytics/consent.ts`, `events.ts` (typed, no PII); GA4 Consent Mode; GA script loads only after consent; privacy page lists GA4.
- **Owner:** GA4 property + measurement ID; confirm events in GA4 DebugView.

### P7 — Quiz bot v1 (deterministic)

- **FE:** `QuizLauncher`, `QuizPopup` small card (D-23), `QuizBubble` with guardrails (D-24, D-24a, O-04); steps color → vibe (auto-skip < 2 vibes) → 1 featured product + "see more" (O-03); loading/error/empty states; lazy-loaded bundle.
- **BE:** `lib/recommend/score.ts` pure scoring; `POST /api/quiz/recommend` with Zod enums and rate limit; quiz events if P6 is DONE.
- **Owner:** Vibe taxonomy (D-10); bubble copy; color/vibe tags on every product.
- **Env required:** none new (reuses Upstash).
- **Acceptance:** Scoring tests cover ties and no-match; screen reader completes quiz; no LCP/INP regression.

### P8 — AI rationale (Claude)

- **FE:** Rationale under result with skeleton; silent fallback on failure or ~4 s timeout; "AI-generated" disclosure.
- **BE:** `POST /api/quiz/explain`; `lib/ai/explain.ts` with `@anthropic-ai/sdk`, timeout + one retry, Zod-validated output ≤ 2 sentences; per-IP rate limit; response cache; feature flag `AI_ENABLED`.
- **Owner:** Anthropic account, API key, monthly spend cap in Console; choose model.
- **Env required:** `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `AI_ENABLED`.
- **Acceptance:** No key in client bundle; quiz works with `AI_ENABLED=false`; burst requests throttled.

### P9 — Launch

- **FE:** Final visual QA on production domain.
- **BE:** Production env on Vercel; Resend sending domain verified; Search Console + sitemap submission; final CSP review.
- **Owner:** All real images (hero banners, product photos, About photo) replacing V-26 placeholders; buy domain + DNS; mailbox; switch `LEADS_FROM_EMAIL`/`NEXT_PUBLIC_SITE_URL` to production; final policy text; review R-01 before real sales.
- **Env required:** production values of all variables.
- **Acceptance:** Site live on the real domain; contact email delivered from verified domain.
