## 2. Rules [USER]

### R1 — Phase gate

A phase may start only when the previous phase is **DONE**. A phase is DONE when **all** of the following are true:

1. Every FE and BE task checkbox in the phase plan is ticked.
2. The phase's own **Acceptance** list is satisfied.
3. The global Definition of Done (section 3) passes.
4. The phase PR is merged into `develop` by the owner.
5. The phase status in section 5 is updated to `DONE`.

### R2 — Fast-track

A later phase may start before its turn **only if**:

1. Every **Owner** task of that later phase is DONE (information supplied, spec clarified, env values set), **and**
2. Every phase listed in its **Depends on** line is DONE.

A fast-tracked phase still gets its own branch and PR. It must not modify code owned by an unfinished phase except through that phase's agreed interfaces.

### R3 — One phase = one PR, one task = one small commit

- Branch per phase from `develop`: `phase/pN-<slug>` (e.g. `phase/p0-foundations`).
- One PR per phase into `develop`. Never commit directly to `main` or `develop`.
- Each task in the phase plan lands as one or more small commits: `[TYPE] Imperative summary` (`[TASK]`, `[FEATURE]`, `[FIX]`, `[ENHANCE]`, `[REFACTOR]`, `[CHORE]`, `[DOCS]`).
- Every commit leaves `pnpm typecheck`, `pnpm lint`, and `pnpm test` green.

### R4 — Environment ownership

- Agents **must not read** `.env`, `.env.local`, `.env.*.local`, or any real secret. Only `.env.example` and `docs/configuration-variables.md` are readable.
- Agents **predict and declare** every variable ahead of time: schema in `lib/env.ts`, placeholders in `.env.example`, purpose and phase in [`docs/configuration-variables.md`](../../configuration-variables.md).
- Every variable not needed by the current phase is **optional** in the schema, so a missing value never crashes `dev`, `build`, or CI. Features that need a missing value degrade to a disabled state.
- The **Owner** sets real values in `.env.local` and Vercel before the phase that requires them starts. A missing required value is a blocker for that phase, not something agents work around.

## 3. Definition of Done (every phase)

1. `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, `pnpm build` all pass locally and in CI.
2. New interactive components have React Testing Library tests; user-facing flows have a Playwright smoke test.
3. Accessibility: keyboard reachable, visible focus, labels, `prefers-reduced-motion` respected; no serious axe issues on touched pages.
4. Performance budget not regressed (mobile): LCP < 2.5 s, INP < 200 ms, CLS < 0.1.
5. No hard-coded user-facing strings outside the copy module (`content/copy/`) — this keeps P5 i18n a mechanical change.
6. `docs/decisions/` updated if a decision changed; `docs/configuration-variables.md` updated if a variable changed.
7. Vercel preview deploy of the PR is reachable (from P1 onward).

### P0 — Foundations & full dependency install

Detailed plan: [`2026-10-22-p0-foundations.md`](./2026-10-22-p0-foundations.md)

- **FE:** Scaffold Next.js App Router (root-based, no `src/`), Tailwind v4, placeholder home page, Vitest + RTL smoke test, Playwright smoke test.
- **BE:** Install every library the roadmap needs; ESLint/Prettier; `lib/env.ts` with all variables optional; `.env.example`; CI workflow; agent env-read deny rules.
- **Owner:** none [USER] — agents run P0 end to end through an open PR; owner only reviews and merges.
- **Env required:** none.
- **Acceptance:** CI green with no secrets; `pnpm build` and `pnpm test:e2e` pass with no `.env.local`.

### P1 — Design system & shell (single locale)

- **FE:** Design tokens (CSS variables), type scale, `components/motion/tokens.ts` + `Reveal`/`Stagger`; Header (transparent over hero → fixed bar, D-25), Footer (O-05), nav; primitives Button, Input, Dialog, Skeleton; shared-element transition spike with fade fallback (D-20, O-06); empty pages Shop, About, Contact, Policy.
- **BE:** `content/copy/vi.ts` copy module; `generateMetadata` helper; `robots.ts`, minimal `sitemap.ts`; record transition decision in `docs/decisions/`.
- **Owner:** Connect the GitHub repo to Vercel (preview per PR); `cp .env.example .env.local`; brand name/logo file, palette and typography direction (or accept agent defaults, A-04); confirm nav items.
- **Env required:** `NEXT_PUBLIC_SITE_URL` (has a localhost default).
- **Acceptance:** Keyboard nav works; Lighthouse a11y ≥ 95 on shell; header switch has no layout shift; no font CLS.

### P2 — Catalog, Home, Shop, Product detail

- **FE:** `ProductCard` + `StatusBadge` + lifestyle clip reveal (D-19, D-19a) using `LifestylePlaceholder` (O-08); `HeroScroll` pinned hero (D-16, O-01); `ProductDragGrid` (D-18, O-07 fallback); `/shop` grid + color/status filters (O-02); `/shop/[slug]` PDP with CTA linking to Contact with product + `purpose` (D-21, D-22a).
- **BE:** `lib/catalog/schema.ts` (Zod), `data.ts`, `index.ts` (`listProducts`, `getProductBySlug`, `getFilters`); build fails on invalid data; image dimension/alt checks.
- **Owner:** Product list (name, price VND, status, colors, vibes, sizes, material, description); front/back photos; hero frame photos (4–5); lifestyle photos when available.
- **Env required:** none.
- **Acceptance:** All products validate; CTA-by-status matrix tested; no CLS on hover or pinned hero; hero and drag grid usable by keyboard and reduced motion; INP < 200 ms while dragging.

### P3 — Contact form & policy pages

- **FE:** Single Contact form (D-22): product prefilled from query, `purpose` selector, email, name, message, honeypot; accessible errors and success state. Policy pages `privacy`, `returns` from `content/policies/`.
- **BE:** `POST /api/contact` with Zod validation, honeypot, rate limit (Upstash); `lib/leads/sink.ts` interface + `email.ts` (Resend); contact disabled gracefully when email env is missing.
- **Owner:** Resend account + API key; owner inbox address; Upstash Redis database; real policy text (returns, privacy).
- **Env required:** `RESEND_API_KEY`, `LEADS_TO_EMAIL`, `LEADS_FROM_EMAIL`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`.
- **Acceptance:** Real email reaches owner from preview; spam honeypot and rate limit tested; form shows a clear disabled state when env is missing.

### P4 — Quality hardening (MVP)

- **FE:** Performance pass (images, fonts, bundle, lazy hover media); axe on all pages; keyboard-only walkthrough; reduced-motion QA; 404/error pages; favicon/manifest; social preview images.
- **BE:** Single-locale SEO: metadata, canonical, sitemap, JSON-LD (`Organization`, `Product`, `BreadcrumbList`); security headers (CSP); Playwright smoke for Home → PDP → Contact.
- **Owner:** Cross-device check on own iOS/Android phones; OG image approval.
- **Env required:** none new.
- **Acceptance:** Performance budgets met on mobile profile; zero serious axe issues; smoke suite green.

### P5 — Internationalization (vi/en)

- **FE:** Move pages under `app/[locale]/`; `LocaleSwitcher` preserving path; replace `content/copy/vi.ts` usage with `next-intl` messages.
- **BE:** `next-intl` routing (`/vi`, `/en`, default `vi`, redirect from `/`); `messages/vi.json`, `messages/en.json`; localized catalog fields; `hreflang` + `x-default`; multilingual sitemap.
- **Owner:** English copy review (or approve agent translation); English product copy.
- **Env required:** none new.
- **Acceptance:** Both locales render every page; switch preserves path; hreflang validated.

### P6 — Cookie consent & GA4

- **FE:** Consent banner (accept / reject / manage), persisted choice; event wiring: `contact_start`, `contact_submit`, `select_item`, `hover_preview_open`, `locale_switch`.
- **BE:** `lib/analytics/consent.ts`, `events.ts` (typed, no PII); GA4 Consent Mode; GA script loads only after consent; privacy page lists GA4.
- **Owner:** GA4 property + measurement ID; confirm events in GA4 DebugView.
- **Env required:** `NEXT_PUBLIC_GA_ID`.
- **Acceptance:** No GA request before consent (tested); events visible in DebugView.

### P7 — Quiz bot v1 (deterministic)

- **FE:** `QuizLauncher`, `QuizPopup` small card (D-23), `QuizBubble` with guardrails (D-24, D-24a, O-04); steps color → vibe (auto-skip < 2 vibes) → 1 featured product + "see more" (O-03); loading/error/empty states; lazy-loaded bundle.
- **BE:** `lib/recommend/score.ts` pure scoring; `POST /api/quiz/recommend` with Zod enums and rate limit; quiz events if P6 is DONE.
- **Owner:** Vibe taxonomy (D-10); bubble copy; color/vibe tags on every product.
- **Env required:** none new (reuses Upstash).
- **Acceptance:** Scoring tests cover ties and no-match; screen reader completes quiz; no LCP/INP regression.

### P8 — AI rationale (Claude)

- **FE:** Rationale under result with skeleton; silent fallback on failure or ~4 s timeout; "AI-generated" disclosure.
- **BE:** `POST /api/quiz/explain`; `lib/ai/explain.ts` with `@anthropic-ai/sdk`, timeout + one retry, Zod-validated output ≤ 2 sentences; per-IP rate limit; response cache; feature flag `AI_ENABLED`.
- **Owner:** Anthropic account, API key, monthly spend cap in Console; choose model.
- **Env required:** `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `AI_ENABLED`.
- **Acceptance:** No key in client bundle; quiz works with `AI_ENABLED=false`; burst requests throttled.

### P9 — Launch

- **FE:** Final visual QA on production domain.
- **BE:** Production env on Vercel; Resend sending domain verified; Search Console + sitemap submission; final CSP review.
- **Owner:** Buy domain + DNS; mailbox; switch `LEADS_FROM_EMAIL`/`NEXT_PUBLIC_SITE_URL` to production; final policy text; review R-01 before real sales.
- **Env required:** production values of all variables.
- **Acceptance:** Site live on the real domain; contact email delivered from verified domain.

### P10 — Post-launch backlog

Socials (Instagram/Zalo/fanpage), Google Sheet/Supabase lead sink, free-text bot, Claude for Startups application. Prioritized by GA4 data; each item is planned as its own phase-sized PR.
