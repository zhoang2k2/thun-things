# P7 — Quiz Bot v1 (deterministic) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lazy-loaded quiz card (colour → vibe) recommends one catalog product plus up to three more from a rate-limited server endpoint, with a capped invitation bubble and consent-gated events.

**Architecture:** Pure scoring in `lib/recommend/`, catalog quiz options exposed by `lib/catalog`, `POST /api/quiz/recommend` route handler (Zod + shared rate-limit factory), client `QuizLauncher` + `QuizBubble` on every page, `QuizCard` loaded on demand.

**Tech Stack:** Next.js 16.4 (Cache Components, route handlers), next-intl 4.14, Zod 4, Upstash, Motion (`LazyMotion`), Vitest + RTL, Playwright + axe.

**Spec:** [`../specs/2026-10-24-p7-quiz-bot-design.md`](../specs/2026-10-24-p7-quiz-bot-design.md).

**Branch / PR:** `phase/p7-quiz-bot` from `develop` → one PR, evidence via `pnpm evidence`.

## Global Constraints

- Scoring weights and tie-breaks exactly as spec section 3; deterministic for equal input.
- API: `POST` only; Zod enums from the catalog; 30 requests / 10 min per client (`thun-things:quiz`); errors as `{ error, code }` JSON without internals; no free text accepted.
- Bubble: first at 20 s, then every 45 s, max 3 per session, silent after dismissal, never while the card is open, never on Contact/Policy/contact result pages, never under reduced motion.
- Launcher and bubble never overlap the consent bar or the mobile order bar.
- Events through P6 `trackEvent` only; params per spec section 4; no PII.
- Keep P4–P6 guarantees: render modes unchanged, Lighthouse budgets, axe zero serious, both locales, CSP unchanged, DR-1/DR-2, client messages scoped (`quiz` namespace added).

## Review Focus

1. **Forged or stale request body** (unknown colour, vibe from a removed tag, extra keys, huge body) → 400 without stack traces. Task 2.
2. **Bubble timers leaking** across client navigations or after unmount → no double bubbles, cap respected across pages within a session. Task 4.
3. **Focus trap/escape** with the card open on mobile while the consent bar is visible. Task 3/5.
4. **API failure or rate limit** → error state with retry, never a blank card. Task 3.
5. **Catalog with < 2 vibes** → vibe step skipped and the request omits `vibe`. Task 1/3.
