## Goal

Every page exists in Vietnamese (`/vi/...`, default) and English (`/en/...`) with natural English copy, a path-preserving language switch, and bilingual SEO (per-locale metadata, `hreflang`, multilingual sitemap), without losing the prerendered shells or any P4 quality guarantee.

## Owner decisions [USER, 2026-10-23]

| ID   | Decision                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P5-1 | `/` **always redirects to `/vi`**; no browser-language detection. English is reached through the switcher.                                                                                                                                 |
| P5-2 | **The agent writes the English copy** from the Vietnamese; the owner reviews it in the PR (non-blocking). English is **rewritten for English readers, not translated word by word**, SEO-aware, never mechanical (rules below).            |
| P5-3 | **Product content is not translated in P5.** Slugs are identical in both locales (`/en/products/hoang-hon-01`). Product pages render the catalog's existing `Localized` fields for the locale; a future CMS will own product translations. |
| P5-4 | **`next-intl`** handles routing and messages (`messages/vi.json`, `messages/en.json`), replacing `content/copy/vi.ts`.                                                                                                                     |

## English copy rules (P5-2)

- Write for an English-speaking visitor; keep meaning and facts, not sentence structure.
- Titles and descriptions use phrases people search: "art t-shirts", "graphic tees", "small-batch", "Vietnam", "limited run" — only where true.
- No marketing filler ("elevate your style", "unleash", "curated just for you"), no exclamation marks, no emoji (DR-2).
- Same facts as Vietnamese: no new promises (shipping, payment, sizes) that the Vietnamese copy does not make. `[Chủ shop cập nhật: …]` placeholders become `[Owner to update: …]`.
- Descriptions stay within 50–160 characters (P4 criterion 6) and are unique per page and locale.

## 1. Routing

- `app/[locale]/` holds every page; `[locale]` is the root segment (root layout `app/[locale]/layout.tsx` renders `<html lang={locale}>`), so the locale is a **root param** read with `next/root-params` (next-intl 4.14's recommended path under Cache Components). `generateStaticParams` returns `vi` and `en`; unknown locales 404.
- `i18n/routing.ts`: `defineRouting({ locales: ['vi', 'en'], defaultLocale: 'vi', localePrefix: 'always', localeDetection: false })`. `i18n/navigation.ts` exports locale-aware `Link`, `redirect`, `usePathname`, `useRouter`.
- `proxy.ts` composes next-intl's middleware with the existing unknown-product 404 rewrite (now `/{locale}/products/:slug`).
- **Redirects:** `/` → `/vi`; legacy unprefixed paths (`/about`, `/contact?product=…`, `/products/<slug>`, `/policy/*`, `/contact/sent|retry`) → `/vi/...` preserving the query (permanent), so links shared before P5 keep working.
- Non-page routes stay unprefixed: `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/manifest.webmanifest`, `/icon.svg`, `/apple-icon`, default `/opengraph-image`.

## 2. Messages

- `messages/vi.json` mirrors today's `content/copy/vi.ts` keys; `messages/en.json` has the same keys (a unit test fails on any missing or extra key, and on empty strings).
- Types: next-intl `AppConfig` augmentation with `Messages` typed from `messages/vi.json`, so `t('…')` keys are checked by TypeScript.
- Server Components use `getTranslations`; Client Components use `useTranslations` with only the namespaces they need passed through `NextIntlClientProvider` (no full message bundle on the client).
- `content/copy/vi.ts` is removed once nothing imports it; the P4 design-rule and copy tests move to the messages.
- Formatting: prices stay VND; `formatPriceVND(value, locale)` uses `vi-VN` (`390.000 ₫`) or `en-US` (`₫390,000`); dates likewise.

## 3. Language switch

- `LocaleSwitcher` in the header: text links `VI` / `EN` (no flags), current locale marked with `aria-current="true"`, each link pointing at the same path and query in the other locale; works without JavaScript (plain links). Keyboard and screen-reader labels from messages ("Tiếng Việt" / "English").

## 4. Bilingual SEO

- `buildMetadata` takes `locale`: localized title and description, canonical `/{locale}/...`, `alternates.languages` = `{ vi: '/vi/...', en: '/en/...', 'x-default': '/vi/...' }`, `openGraph.locale` `vi_VN` / `en_US` with `alternateLocale`.
- Sitemap: every page in both locales with `alternates.languages` per entry; result pages (`/contact/sent|retry`) stay out and keep `noindex`.
- OG images under `app/[locale]/…` render per locale (English status labels and price format); the default `/opengraph-image` stays the shared wordmark.
- JSON-LD gains `inLanguage`; `url` points at the localized page.
- `llms.txt` is written in English and lists both locales' key pages and every product.
- All P4 SEO, axe, keyboard, reduced-motion, CSP and smoke checks run for both locales.

## 5. Forms and leads

- Forms, errors, result pages and confirmation copy follow the page locale; server functions receive the locale (hidden field validated against the routing locales) and return localized messages.
- `Lead.locale` becomes `'vi' | 'en'`. The owner notification stays Vietnamese and adds a line "Ngôn ngữ khách: EN/VI". Customer confirmation (P9) will use the lead's locale.
- No-JS result redirects go to `/{locale}/contact/sent|retry`.

## Testing

- Unit: message key parity and non-empty values; `formatPriceVND` per locale; `buildMetadata` alternates and canonicals; sitemap alternates; locale-aware lead schema and owner email line.
- E2E: every page renders in both locales with the right `lang`; switch preserves path and query; `/` and legacy paths redirect; unknown locale 404; `hreflang` and canonical per page; no Vietnamese UI strings on `/en` pages outside product content and placeholders; existing P3/P4 specs parameterised over both locales.
